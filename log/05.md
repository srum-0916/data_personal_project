# 5차시: 변수 선택·데이터 전처리

- 오늘 결정한 것:
  원본에서 사전학습·대화용·분야별 추가 학습·모델 병합의 네 유형 4,502행을 선택했다. 나머지 유형 74행은 범위에서 제외했다. 입력은 모델 크기와 모델 유형, 예측 대상은 지시 수행 점수이며 추론·수학 점수와 구조·정밀도·대화 형식은 보조 정보로 남겼다. Type을 ‘모델 유형’으로 바꾸고 범주 이름을 한국어로 정리했다. IFEval Raw×100은 IFEval과 같으므로 중복 점수 열을 남기지 않았다.

  전처리 과정은 다음과 같다.

  | 단계 | 제외 행 수 | 남은 행 수 | 근거 |
  |---|---:|---:|---|
  | 네 유형 선택 | 74 | 4,502 | 유형별 빈도와 분석 범위 |
  | 유효성 점검 | 3 | 4,499 | 양수가 아닌 모델 크기 제외; 세 점수는 유한한 0~100인지 확인 |
  | 유형 충돌 모델 제외 | 58 | 4,441 | 원본 전체에서 같은 모델명이 둘 이상의 Type으로 기록됨 |
  | 나머지 반복 평가 정리 | 47 | 4,394 | 모델별 원본 순서의 첫 기록 유지 |
  | 모델 크기 극단 구간 제외 | 273 | 4,121 | Q1=6.061B, Q3=12.248B, IQR=6.187B; 바깥 울타리 Q1−3IQR=−12.500B, Q3+3IQR=30.809B |

  최종 크기 범위는 0보다 크고 30.809B 이하이다. 네 유형은 모델 병합 1,651개, 분야별 추가 학습 1,646개, 대화용 580개, 사전학습 244개이다. 최종 4,121행·9열로 모델명 중복과 핵심 입력·예측 대상의 결측치가 없다. 모델 구조의 결측치 6개는 보조 정보로 남겼다.

- AI에게 보낸 프롬프트(원문):
  > 내 github 조작할 수 있다고 했지? 그러면 분야별 추가 학습 모델과 병합 모델만 가져오되 기초통계자료를 기반으로 해서 너무 값이 튀는 기록들은 쳐내줘. 그래서 md1~5까지 다 바꿔주고 data에 있는 cleared된 CSV도 말했던 대로 바꿔줘.

- AI가 준 것 중 고치거나 버린 것과 그 이유:
  두 유형만 유지하던 전처리를 수정했다. 크기는 전체 네 유형의 중복 정리 후 분포에서 3×IQR 기준을 한 번 계산하여 적용했으며, 유형마다 별도의 기준으로 유리하게 선별하지 않았다. IQR 밖이라는 사실은 오류의 증거가 아니므로 대형 모델을 ‘잘못된 데이터’라고 부르지 않고 분석 범위를 제한한 것으로 기록한다. 예측 대상 점수가 높거나 낮다는 이유만으로는 삭제하지 않았다. 분류 제안 대신 수치 점수를 예측하는 회귀 분석을 선택했다.

  **한계와 향후 검증:** 30.809B 초과 모델에도 유효한 기록이 포함될 수 있어 결과를 전체 모델 크기로 일반화할 수 없다. 최종 평가는 크기 제한 전 유효 데이터(4,394행)에서도 함께 확인하는 민감도 분석이 필요하다. 유형 충돌은 메타데이터 차이일 수 있으며, 첫 기록 유지로 평가 조건 정보가 손실될 수 있다. 이번 크기 기준은 탐색용 전체 데이터에서 정했으므로 엄격한 새 데이터 예측 평가에서는 학습 데이터만으로 기준을 정하고 원래 테스트 분포에 대한 성능도 보고해야 한다. 같은 계열 모델이 양쪽에 나뉘는 문제도 분할 시 점검한다. 모델 학습과 성능 평가는 아직 하지 않았다.

- 느낀 점:
  전처리는 데이터를 줄이는 작업이 아니라 분석 목적에 맞는 기준을 세우는 과정임을 배웠다. 같은 모델도 평가 조건와 유형이 다르게 기록될 수 있어 확인이 필요하며, 처리 이유와 남은 한계를 함께 설명해야 한다고 느꼈다.
