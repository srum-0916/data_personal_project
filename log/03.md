오늘 결정한 것:
선택한 Open LLM Leaderboard 데이터가 프로젝트의 데이터 조건에 맞는지 확인했다. 원본은 4,576행, 36열로 구성되어 있어 행 50개, 열 6개 이상 조건을 충족한다.
대화용 여부와 대화 형식 사용 여부는 뜻을 쉽게 이해할 수 있도록 숫자 0·1 대신 텍스트로 표시했다. 이후 GitHub와 파이썬에서 활용하기 위해 원본 데이터를 SV 형식으로 변환했다.
main.py는 원본 CSV를 GitHub 주소에서 직접 불러와 기초통계를 확인하는 Streamlit 앱으로 만들었다. 행·열 수, 결측치, 중복 행 수, 평균, 중앙값, 표준편차, 최솟값과 최댓값 등을 확인하고, 히스토그램과 박스플롯으로 분포를 살펴보도록 했다.
분석 방법도 검토했다. 모델 크기만으로 지시 수행 점수를 설명하는 회귀에서는 결정계수가 낮게 나왔다. 이를 통해 모델 크기만으로는 점수 차이를 충분히 설명하기 어렵다는 것을 확인했다. 이후 평가 점수로 두 유형을 구별하는 분류 방법을 후보로 검토했다. 아직 분류 모델의 학습과 성능 평가는 진행하지 않았다.


AI에게 보낸 프롬프트(원문):
근데 결과적으로 0 1 로 표시 안 하고 그냥 작성해도 테스트 데이터라고 보기 어렵지 않아? 저기서 0 1 하지 말고 그냥 텍스트로 쓰는 건 어때? 보기 편하게
아까 그 엑셀 원본 파일을 CSV 파일로 변환시켜줘.

AI가 준 것 중 고치거나 버린 것과 그 이유:
범주를 0과 1로 표시한 방식은 의미를 바로 이해하기 어려워 ‘사전학습/대화용’, ‘미사용/사용’으로 바꿨다. 범주를 숫자로 바꾸는 것과 실제 수치형 변수를 확보하는 것은 다르므로, 수치형 열 조건은 모델 크기와 세 가지 평가 점수로 충족하도록 했다.
처음 만든 앱은 두 유형의 점수 비교와 회귀 그래프가 중심이었다. 하지만 이번 main.py의 목적은 원본 데이터의 기초통계를 분석하는 것이므로, 원본 CSV의 구성과 결측치, 대표값, 분포를 확인하는 앱으로 수정했다.
또한 박스플롯을 그리는 것 자체가 분류 분석은 아니라는 점을 확인했다. 박스플롯은 집단의 분포를 비교하는 시각화이고, 분류는 데이터를 학습해 새로운 데이터의 범주를 예측하는 방법임을 구분했다.

느낀 점:
데이터를 분석하기 전에 행과 열의 수뿐 아니라 각 열의 의미와 자료형을 확인해야 한다는 것을 배웠다. 같은 데이터라도 원본을 살펴보는 단계와 질문에 맞게 가공하는 단계의 목적이 다르다는 점도 알게 되었다.
처음에는 회귀선의 결정계수가 낮으면 분석이 잘못된 것이라고 생각했지만, 모델 크기만으로 점수를 설명하기 어렵다는 결과도 의미가 있다는 것을 알게 되었다. 앞으로는 그래프를 보기 좋게 만드는 것보다 질문에 맞는 분석 방법을 선택하고, 실제 결과를 근거로 해석하는 데 집중하고 싶다.
